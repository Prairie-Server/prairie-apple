The big idea

Let the phone set up the TV

You already ship QR pairing on the sign-in screen. Extending it so the iOS app pushes the server address and the session turns the worst part of first-run (thumb-typing a URL and password) into two taps — the same pattern Apple uses to set up an Apple TV from an iPhone.

① Server handoff

TV shows a short code / QR. The iOS app (already signed in to your server) sends the normalized address straight over — no typing.

② Session handoff

Phone approves with Face ID and passes a scoped token, so the TV lands signed-in. Falls back to QR or password on any other phone.

✓ Have: QR pairing + match code Needs: iOS “Set up Apple TV” + token grant Needs: server pairing endpoint

Transport options: local pairing over the same network/account, or the existing device-code channel (RFC 8628) with verification_uri_complete in the QR. Bonjour LAN discovery is a nice-to-have but not required for handoff.

Why phone-first

Sign-in patterns, compared

Remote text entry is the single biggest pain point on TV (Apple: “design your UI to avoid excessive text input”). Every major app moves the typing to a second device.

PatternRemote typingUsed byNotes
Companion handoff our pick none Apple TV setup, Plex/Emby account model iOS app pushes server + session. Best UX; needs the pairing work above.
QR scan none Netflix, YouTube, Max, Plex TV shows QR, phone camera opens approve page. You already have this.
Short device code low Disney+, Hulu, Spotify, Prime “Enter code on your phone.” RFC 8628 standard; graceful fallback.
On-screen keyboard highest Universal fallback only Hunt-and-peck username + password. Keep it, but never lead with it.

Applied throughout

The 10-foot rulebook

Every frame follows these. Numbers are baked into the shared CSS tokens.

01Safe area ~90px sides / 60–68px top-bottom; backgrounds bleed, content doesn’t.
02Big, heavy type — body ≈26pt, titles ≥48pt, hero 80–92pt. Never thin weights.
03Dark, not pure-black surfaces; off-white #EDEDED text, never #FFF on #000 for large fields.
04Scrim behind text on art — Aurora layers a gradient + vignette for legibility.
05Focus = lift, not hover — scale + ring + shadow; pills invert to white. No cursor.
06Few focusables per screen; straight D-pad paths; default focus on the primary action.
07Kill text entry — QR / handoff first, keyboard last.
08Normalize the URL — auto add https:// + default port; accept bare IPs.
09Delay sign-in; ≤5 steps; launch screen mirrors the app, no logo splash.
10Connecting capped ~15s with an actionable error (edit address / retry).
11Subtle, cinematic motion — crossfades + focus parallax; honor Reduce Motion.
12Selection over input — profile pick is taps, never typing.

Sources: Apple Human Interface Guidelines (tvOS Layout, Focus, Typography, Managing accounts, Loading), RFC 8628 OAuth Device Authorization Grant, Jellyfin Quick Connect / Swiftfin, NN/g (response times, smart-TV usability), BBC GEL, Microsoft “Designing for Xbox and TV.” Full brief on request.

⚠ Cross-repo coordination (per workspace conventions)

  • silo-server — owns auth/session + pairing. The companion handoff needs a pairing/token-grant endpoint (extend the existing QuickConnect/QR flow). Bonjour discovery, if pursued, is also server-advertised.
  • silo-android — TV client should stay aligned; the same handoff + phone-first sign-in pattern ought to land on Android TV ↔ Android phone. Compare before finalizing copy/flow.
  • silo-apple — this repo: new SwiftUI first-run views + an iOS “Set up Apple TV” surface. Tokens already exist in Theme/*.swift; these mockups map 1:1 (1pt = 1px).
